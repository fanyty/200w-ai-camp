# 提示词 · 02.1 设计系统展示页生成器

仅在用户要求，或实际需要单独比较、确认共用组件风格时读取并生成。本期页面原型已足够展示时，无需额外展示页。

> **前置依赖**：
> - `output/DESIGN.md` 已存在（由 02-设计系统设计师 产出）
> - `output/tokens.css` 已存在（由 02-设计系统设计师 产出）
>
> **产出**：`output/design-system-showcase.html`（复用既有样式资源）
>
> **用途**：将本次需要比较或确认的共用规则、组件与状态真实渲染，帮助用户判断设计效果。

---

# Task / 任务目标
根据 `DESIGN.md` 和 `tokens.css`，生成一个**完整、可独立查看**的 HTML 评审页，资源加载方式符合已确认环境。

**核心目标**：
- **一目了然**：打开页面即可看出本次展示的风格与组件效果
- **覆盖实际需要**：围绕本次需要比较或确认的设计决定、共用组件及相关 Token 组织，不为填满章节展示无关内容
- **真实渲染**：不是"写个表格说颜色是 #xxx"，而是**真实渲染那个颜色/字体/间距/组件**，让评审人看到实际效果
- **可以长**：这是评审页，单页长滚动，内容完整优先于"一屏装下"

---

# Input / 输入说明

1. `DESIGN.md`：实际设计决定、共用规则与可复用 CSS；按内容定位，不依赖固定章节编号
2. `tokens.css`：56 个 CSS 变量（Surface/Foreground/Border/Accent/Semantic/Typography/TypeScale/Spacing/Radius/Elevation/Focus/Motion/Layout）

**这两个文件是唯一真理来源**。展示页的所有内容都从这两个文件提取，不发明新内容。

---

# Implementation Requirements / 实现要求

## 1. Tech Stack & Resources（技术栈与资源）

- **核心技术**：原生 HTML；布局可用 CSS 或 Tailwind 工具类。
- **资源方式**：沿用产品原型已确认的运行环境，可用内联/本地 CSS、字体与 SVG；环境允许且资源可达时也可用 CDN，不强制外链或机械新增离线打包流程。在线资源沿用已确认依赖与版本；离线或受限环境确保实际使用的资源本地可用。
  - 字体：从 tokens.css 的 `--font-display` / `--font-body` / `--font-mono` 提取；系统或已有本地字体无需请求 Google Fonts。
  - 图标：使用实际 SVG，可沿用已具备的 Phosphor Icons，不要求额外引入在线图标库。

- **设计 Token 加载（关键要求）**：
  按 `页面HTML规范.md` 的资源规则加载已有 `tokens.css`，本页通常引用同目录的 `./tokens.css`；单文件独立分发时才原样内联。全文使用 `var(--xxx)` 引用，**禁止硬编码 Hex 颜色值**（hex 只允许出现在权威 Token 定义、其原样内联副本和色板展示区的"Hex 值标注"文字中）。

---

## 2. 内容参考（按本次展示需要选用）

以下内容可按需要选用、合并或调整顺序，不要求固定区块数。展示实际相关的规则与组件状态，已有产品原型可直接承载的内容无需重复制作。页面可采用单列滚动布局，内容较多时用章节标题分隔。

### Section 1: Hero（设计系统名片）

- **设计系统名称**（H1，用 `--font-display`，最大字号）
- **Category** 标签（来自 DESIGN.md 文件头的 Category）
- **一句话摘要**（来自 DESIGN.md 文件头的摘要）
- **视觉方向**：简述 DESIGN.md 中已确认的风格
- **设计签名**：按 DESIGN.md 的实际定义呈现其独特视觉特征

> 这一节让评审人 3 秒内 get 到设计气质。

### Section 2: 设计理念

用卡片或分栏布局呈现：
- **用户情绪**：用户使用时应感到什么？
- **设计决策理由**：为什么选浅色/深色？为什么选这种风格？
- **风格定位**：已确认的风格特征及其与产品的关系
- **参考先例**：DESIGN.md 已记录的真实产品/设计系统及参考内容，可用表格或卡片呈现

### Section 3: 色彩系统

展示与本次比较相关的颜色，使用真实色块或组件。

可按以下分组呈现：

**3.1 Surface 色板**
- 每个变量一个色块：`--bg` / `--surface` / `--surface-warm` / `--surface-raised` / `--surface-overlay`；以实际 tokens.css 的变量为准
- 色块上标注：变量名、Hex 值、用途说明（来自 DESIGN.md 的实际定义）

**3.2 Foreground / Text 色板**
- `--fg` / `--fg-2` / `--muted` / `--meta`
- 色块用**实际文字渲染**（在对应背景上显示"This is foreground text"），让评审人直接看到可读性

**3.3 Border 色板**
- `--border` / `--border-soft`
- 用实际带边框的盒子展示

**3.4 Accent 色板**
- `--accent` / `--accent-hover` / `--accent-active` / `--accent-on`
- 用按钮的真实状态展示（default/hover/active），让评审人看到 accent 的实际效果
- **强调色纪律说明**：沿用 DESIGN.md 中已确定的使用约束

**3.5 Semantic 色板**
- `--success` / `--warn` / `--danger`
- 用状态提示组件展示（成功/警告/错误的 Toast 或 Badge）

> 每个色块必须显示 Hex 值，让评审人能核对。

### Section 4: 排版系统

**4.1 字体展示**
- Display 字体：用 `--font-display` 渲染一段大标题示例（如"The quick brown fox"）
- Body 字体：用 `--font-body` 渲染一段正文示例
- Mono 字体：用 `--font-mono` 渲染一段代码/数据示例
- 每个标注：font stack、字体选择理由（来自 DESIGN.md）

**4.2 字号梯度（Type Scale）**
- 从 `--text-xs` 到 `--text-4xl`，每个字号实际渲染一行示例文字
- 标注像素值，让评审人看到梯度差异

**4.3 Letter-spacing 规则**
- 用表格展示：ALL CAPS / Display / 标题 / 小文本 / UI 标签 / 正文 各自的 letter-spacing 值（来自 DESIGN.md 的排版规则）
- 每行实际渲染对应文字，让评审人看到字距差异

**4.4 Line-height**
- 展示 `--leading-body` 和 `--leading-tight` 的实际段落效果

### Section 5: 间距体系

- 用**可视化色条**展示 `--space-1` 到 `--space-12` 的实际尺寸（每个间距用一个对应宽度的色条）
- 标注像素值
- 展示 Section rhythm：`--section-y-desktop` / `tablet` / `phone` 的对比

### Section 6: 布局与空间

- **布局示例**：展示 DESIGN.md 已确定的布局与信息层级；其中采用 Bento Grid 时才展示网格卡片
- **Container**：标注 `--container-max` / gutter 值
- **深度与层级**：展示 `--elev-flat` / `--elev-ring` / `--elev-raised` 三个层级的卡片，让评审人看到"浮起来"的效果

### Section 7: 圆角与焦点（来自 tokens.css）

- **圆角梯度**：`--radius-sm` / `--radius-md` / `--radius-lg` / `--radius-pill`，每个用一个对应圆角的盒子展示
- **Focus Ring**：展示 `--focus-ring` 的实际效果（一个聚焦状态的输入框/按钮）

### Section 8: 组件库

复用 DESIGN.md 中的实际组件 CSS，已有共享样式直接引用，不在展示页另存一套；渲染本次需要展示的组件及其已定义状态。以下为常见示例，按实际组件选用：

- **按钮**：default / hover / active / focus-visible / disabled，使用已定义的变体
- **卡片**：default / hover（体现交互哲学：阴影提升型/色彩响应型/物理位移型）
- **输入框**：default / focus / error / disabled
- **徽章/Badge**：各种语义色
- 其他 DESIGN.md 中已定义且与本次展示相关的组件

> 每个组件必须**真实可交互**（hover/active 能看到状态变化），不是静态截图。

### Section 9: 动效与交互物理

- **Motion 时长**：展示 `--motion-fast` (150ms) 和 `--motion-base` (200ms) 的实际过渡效果（一个 hover 元素）
- **Easing 曲线**：展示 `--ease-standard` 的曲线，并用实际动画演示
- **微反馈演示**：复用 DESIGN.md 中按钮按压、输入框聚焦、卡片悬停的实际 CSS
- **进场动画**：展示 DESIGN.md 已定义且与本次比较相关的进场效果
- **prefers-reduced-motion 说明**：标注本系统如何处理无障碍

### Section 10: 品牌情感与声音

- **品牌关键词**：使用 DESIGN.md 已定关键词，用大字呈现，不另凑数量
- **情感化细节**：空状态 / Loading / 404 的实际样式示例（真实渲染，不是描述）
- **设计准则**：按需要呈现 DESIGN.md 已有的关键准则

### Section 11: 设计禁忌

- 用**对比展示**呈现每条禁忌：
  - 左侧：✅ 正确做法
  - 右侧：❌ 禁止做法（用红色叉号标注）
- 每条附理由（来自 DESIGN.md 对应内容）

> 这是最有评审价值的部分——让评审人看到"什么不能做"。

---

## 3. Layout & Responsiveness（布局与响应式）

- **桌面端优先**：以 1440px 宽度为主设计参考，主体内容 1200-1400px 居中
- **移动端适配**：约 375px 单列滚动（次要，评审场景以桌面为主）
- **长滚动**：页面可以很长（2000-5000px 高度正常），用清晰的 Section 锚点导航
- **建议**：内容较多时加锚点导航，只列实际展示的区块

---

## 4. Visual Aesthetics（视觉与美学）

- **严格遵守 DESIGN.md**：这个展示页本身必须**践行**它所展示的设计系统——用 `var(--xxx)` 引用实际 token，沿用已确认的布局与签名级视觉决策
- **展示效果可比较**：布局与内容应让用户清楚看到实际样式和状态差异
- **克制但完整**：信息密度高但不拥挤，每个 Section 有呼吸空间

---

## 5. Content Rules（内容规则）

- **真实渲染**：颜色用真实色块，字体用真实渲染，间距用真实尺寸，组件用真实交互——**禁止只用文字描述**
- **标注完整**：每个展示元素标注：变量名、数值、用途、设计理由（来自 DESIGN.md 对应章节）
- **不发明内容**：所有文案从 DESIGN.md 提取，不自己编设计理念
- **Hex 值显示**：色彩区每个色块必须显示 Hex 值，方便评审核对

---

## 6. Code Style（代码风格）

- 完整 HTML 结构（DOCTYPE、html、head、body、meta charset、viewport）
- `<title>`：`{设计系统名称} · Design System Showcase`
- Tailwind Class 有条理，2 空格缩进
- 组件和动效 CSS 优先复用 DESIGN.md 中的实际定义

## 生成完整性约束（写入时直接满足）

以下规则约束产出内容，不需要逐条另起一轮检查；发现实际缺陷时修正并验证受影响部分：

1. 页面能按实际相对路径加载 tokens.css 和所用共用样式；明确单文件交付时原样内联。
2. Hex 颜色只允许出现在权威 Token 定义、其原样内联副本和色板展示区的 Hex 标注文字中，组件 CSS 使用 `var(--xxx)`。

4. 展示的色板都有真实渲染的色块，文字色与对应背景一同呈现。
5. 展示的交互组件具备其已定义的相关状态（如 default / hover / active / focus）。
