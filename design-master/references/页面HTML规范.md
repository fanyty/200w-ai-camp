# 页面 HTML 规范

供 `design-master` 生成页面 HTML 时按需读取。每份 HTML 是独立、完整、响应式的高保真静态原型，用于让产品、业务和技术团队理解页面功能；最终视觉标准遵循已确认的 `DESIGN.md`。首次展示与后续完善节奏由 `SKILL.md` 统一规定。

## 输入与输出

- 页面内容：新增页面为 `output/pages/{PAGE-ID}.md`，既有页面沿用按 PAGE ID 确认的真实路径，提供页面 ID、信息层级、模块、字段与关键交互。
- 设计系统：`output/DESIGN.md`，提供视觉规范、组件 CSS 和动效 CSS。
- 设计 Token：`output/tokens.css`，提供颜色、圆角、阴影、字体等 CSS 变量。
- 页面范围：按 requirements 与蓝图一致的 `scope` 选取 `output/页面清单.md` 的本期页面；不得为范围外未启动的 `planned` 页面创建空壳 HTML。
- 输出：新增页面直接写入与输入 MD **同目录、同主文件名**的 `.html` 文件，例如 `output/pages/PAGE-F01-01.md` 对应 `output/pages/PAGE-F01-01.html`，不得缩写文件名或增加 `html/` 子目录。既有 HTML 与 MD 内容身份唯一且一致时沿用真实路径，不因旧文件名不同而强迁移或覆盖别的 PAGE ID。
- `<head>` 包含从页面 MD 元信息原样读取的稳定 ID，供 TDD 与 `/goal` 恢复映射：
  ```html
  <meta name="page-id" content="PAGE-F01-01">
  ```

## 技术与设计系统

- 使用原生 HTML；布局可用 CSS 或 Tailwind 工具类（flex、grid、spacing、responsive），禁止引入 Bootstrap、Ant Design、Material UI 等第三方 UI 框架。
- 资源方式遵循已确认环境：可用内联/本地 CSS、字体与 SVG；环境允许且资源可达时也可用 CDN，不强制外链，不为原型机械增加离线打包流程。采用在线资源时记录实际依赖与版本，不能新增蓝图未确认的外部依赖；离线或受限环境保证所需样式与图标在本地可用。
- 按 `tokens.css` 的 `--font-display` / `--font-body` 使用对应字体栈；系统或已有本地字体无需请求 Google Fonts。
- 使用真实 SVG 功能图标，可用已具备的 Phosphor Icons；不得用文字或 `✨ / 🚀 / 🎯 / ⚡ / 🔥 / 💡` 等 emoji 替代。
- 原型集通过相对路径加载已有 `tokens.css`（如 `pages/` 中页面引用 `../tokens.css`），不逐页复制 Token。只有明确要求单个 HTML 独立分发时，才将其 `:root {}` 及已有的 `[data-theme="dark"]` 块原样内联。组件颜色、圆角、阴影和字体使用 `var(--xxx)`，不硬编码 Token 值。
- Hex 颜色只允许出现在权威 Token 定义或其原样内联副本中，组件 CSS 全部引用变量；禁止使用 Tailwind 默认靛蓝/紫色 `#6366f1 / #4f46e5 / #8b5cf6 / #7c3aed / #a855f7` 代替设计系统的 `--accent`。
- 组件与动效 CSS 沿用 `DESIGN.md` 中对应的实际定义，优先引用已有本地共享样式；确有多页重复且尚无共享文件时，可将共用部分提取一次，页面只补自身差异，不为单页强建共享文件。特殊效果可补少量自定义 CSS，不大规模重写 Tailwind 默认样式。共享 CSS 随原型目录一起交付，引用路径按实际 HTML 位置计算，不新增构建或打包流程。
- 使用完整 HTML 结构（DOCTYPE、html、head、body、meta charset、viewport）；`<title>` 匹配页面名称，2 空格缩进，工具类组合清晰。

## 页面内容与交互

- 完整覆盖页面文档已确认的核心信息、模块、示例文案和字段；导航、主操作、辅助说明、Tab、过滤器、列表、统计、表单和反馈按页面实际需要呈现。
- 可补符合业务语境的示例文案和 Mock 数据，不改变已确认的信息结构和层级。
- 展示典型使用中的正常态，不把空状态、错误态、加载态堆成状态展示页；若空状态本身是页面核心设计，则按设计展示。
- 列表数据足以呈现典型信息密度、长短内容和主要业务差异；统计使用合理具体数值；正文体现真实内容层次。不按固定条数、段落数凑量。
- 禁止 Lorem Ipsum、`Item 1`、`TODO`、空白占位，以及页面上的设计理念或思考过程说明。
- 使用少量内联脚本完成必要的状态切换和即时反馈，无需真实数据提交；所有可点击元素具有 hover、active、focus-visible 反馈。
- 使用语义化标签及合理的 aria 属性。

## 布局与视觉

- 遵循 `DESIGN.md` 的设计意图和禁忌，以清楚传达页面功能为先。通过信息层级、留白、栅格、细边框和空间层次形成高保真视觉，不堆砌装饰。
- 桌面端以约 1440px 视口为参考，主体宽度建议 1080–1200px 并水平居中；上下空间均衡，避免内容挤在顶部、底部大片空白。仪表盘或概览可采用 Bento Grid。
- 按信息架构选择单列、主内容加侧栏或多列卡片，体现清晰的视觉优先级。
- 约 375px 移动视口使用单列纵向布局，核心任务前置，字号可读、点击区域充足、间距合理；用 CSS 媒体查询或 Tailwind 响应式前缀控制断点。

## 最终交付标准

每个本期已确认页面均有内容完整、路径及页面 ID 正确、Token 一致、响应式可用且符合已确认视觉标准的 HTML。
