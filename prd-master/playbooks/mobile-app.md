# 移动 App 调研 Playbook

> 本文件是定向查证的资料入口，不是必做清单。只读取能回答当前未决问题的部分；不设竞品数量或数据项配额。已有证据足够即停止。下面的历史数值、市场判断与渠道只是线索，实际使用前必须查证来源、日期及适用范围，不能直接当成当前事实或产品门槛。

## 适用场景

C 端 iOS/Android App、小程序、Web App（C 端）、消费类产品

## 一、按当前问题选择竞品

### 直接竞品

**找法**：
- AppStore 搜索关键词 → 查看与当前场景相关的结果和排名
- 七麦数据 / App Annie / Sensor Tower 看品类榜
- 联网搜索：`{产品定位关键词} App 推荐`
- 小红书搜 `{品类} App 推荐` / `{品类} App 对比`
- 知乎搜 `好用的 {品类} App`

**记录**：
- App 名 / 公司 / iOS+Android 都有吗
- 一句话定位
- 与当前问题相关的核心功能
- 商业模式（订阅/广告/电商/打赏/付费下载）
- 公开下载量 / DAU / MAU（找得到的）
- 主要用户画像

### 间接竞品

竞争用户时间/钱包的产品。例：做"健身打卡 App"时，可查证 Keep、微信运动、传统线下健身房等替代方案是否服务同一场景，不预设其市场地位或传播效果。

## 二、抓 App Store 页面

**用当前环境可用的页面读取能力查看**：
- AppStore 详情页（提取截图描述、版本更新历史、评论）
- Google Play 详情页
- 官网（如果有）

**关键字段**：
- AppStore 描述（首句最重要）
- 截图数量 + 各截图标题（暴露作者主推什么）
- 最新版本更新内容（暴露当前迭代方向）
- 评分分布（5/4/3/2/1 星各多少）
- 总评论数

## 三、挖差评（C 端核心信号源）

**C 端的差评是最便宜的用研**。

### 可选渠道

| 渠道 | 用法 |
|------|------|
| **AppStore** | 详情页 → 评论 → 排序按"最新" + 筛选"1星 / 2星" |
| **Google Play** | 同 AppStore |
| **小红书** | 搜 `{App名} 缺点` / `{App名} 卸载` / `{App名} 替代` |
| **知乎** | 搜 `{App名} 为什么不好用` / `{App名} 替代` |
| **微博** | 搜 `{App名} 难用` / `{App名} bug` |
| **B 站** | 搜 `{App名} 测评` 看负面测评视频的评论区 |

### 挖什么

- **卸载原因**
- **功能缺失抱怨**
- **性能/卡顿/闪退抱怨**
- **广告/付费抱怨**
- **客服/退款抱怨**
- **隐私/数据担忧**

### 输出格式

每条原话引用 + 来源 + 日期。

## 四、行业 Benchmark

### 可能相关的指标

下表机构与报告名称仅作查找线索；实际数值须来自本次取得的真实资料，记录来源、日期、样本和适用范围，不能直接用作项目目标。

| 指标 | 需核对的统计口径 | 查找线索 |
|------|---------|--------|
| **次日留存** | 新用户起点、次日定义、活跃事件、品类与获取渠道 | Sensor Tower, AppsFlyer benchmarks |
| **7 日留存** | 第 7 日留存或 7 日内回访、用户群与活跃事件 | Sensor Tower, AppsFlyer benchmarks |
| **30 日留存** | 第 30 日留存或 30 日内回访、用户群与活跃事件 | Sensor Tower, AppsFlyer benchmarks |
| **DAU/MAU 黏性** | 活跃事件、去重方式、日均或指定日 DAU、月度窗口 | Sensor Tower, AppsFlyer benchmarks |
| **平均使用时长** | 人均或会话均值、前后台计时、品类与观察周期 | QuestMobile, Mob 研究院 |
| **付费转化率** | 下载、注册或试用分母，首次付费事件及转化窗口 | RevenueCat State of Subscription |
| **ARPU/ARPPU** | 全体用户或付费用户分母、收入口径与时间窗 | App Annie, Sensor Tower |
| **CAC** | 获客成本范围、归因窗口、平台、地区与渠道 | Liftoff, AppsFlyer |
| **AppStore 评分** | 商店地区、版本、评分总量与采集日期 | AppStore 实际页面 |

### 数据源

- **Sensor Tower**（App 下载/营收数据）
- **App Annie / data.ai**（同上）
- **QuestMobile**（中国市场，DAU/MAU 等）
- **Mob 研究院**（中国市场报告）
- **极光数据**（中国市场）
- **AppsFlyer Benchmarks**（归因、留存）
- **RevenueCat State of Subscription**（订阅类）
- **Liftoff Mobile App Trends**（CAC）

## 五、关键判断辅助

### 这个 App 值不值得做的检查清单

- [ ] 实际使用频次是否适合目标场景与价值，不把高频作为所有 App 的门槛
- [ ] 是否有自然传播触发点（分享/邀请/拼团/榜单）
- [ ] 冷启动方案是否清晰（应用市场 ASO / 内容 / KOC / 合作 / 投放）
- [ ] 留存机制是否设计（消息推送 / 内容更新 / 任务体系 / 社交关系）
- [ ] 变现模型是否清晰（订阅 / 内购 / 广告 / 电商）
- [ ] 监管风险（涉黄涉政 / 数据出境 / 未成年保护 / 平台抽成）

### 中国 C 端 App 特殊点

- 平台分发：按已确认平台查 AppStore 中国区、实际安卓渠道或小程序入口
- 应用商店分发需要时再查 ASO；渠道选择沿用目标用户的真实获取路径
- 区域订阅转化率按同品类、同周期与同口径查证，不默认套用中美比例
- 抖音/快手/视频号等渠道的获客效果按目标客群与现有证据判断
- 广告接受度与付费意愿需要对应用户证据
- 隐私合规：按业务与数据范围查证个保法、数据安全法及等保等适用要求

## 六、调研输出模板

按实际查证内容写入 `{项目名}/evidence/competitors.md` 或 `benchmark.md`；未做的研究不生成空报告。
