# SaaS 调研 Playbook

> 本文件是定向查证的资料入口，不是必做清单。只读取能回答当前未决问题的部分；不设竞品数量或数据项配额。已有证据足够即停止。下面的历史数值、市场判断与渠道只是线索，实际使用前必须查证来源、日期及适用范围，不能直接当成当前事实或产品门槛。

## 适用场景

B 端企业软件、协作工具、垂直行业 SaaS、Vertical AI 工具、订阅制工具

## 一、按当前问题选择竞品

### 直接竞品

**找法**：
- 联网搜索：`{产品定位关键词} alternatives` 或 `best {品类} software {实际年份}`
- 联网搜索：`{知名头部产品} vs` 看推荐对比的工具
- Product Hunt 同标签：`https://www.producthunt.com/topics/{topic}`
- G2 / Capterra 品类列表

**记录**：
- 公司名 / 产品名 / 官网
- 一句话定位
- 与当前问题相关的核心功能
- 定价模型
- 用户规模（融资、客户数、ARR 等公开数据）

### 间接竞品

**找法**：解决相似问题但形态不同的工具
- 例：如果做"AI 写周报"，间接竞品是 Slack（聊天工具，员工已经在用）、Notion（笔记+协作）、传统 BI 工具

## 二、抓官网（每个竞品）

**按当前问题用页面读取能力选择相关页面**：
- 主页（提取定位、核心价值主张）
- 产品/功能页（提取功能列表）
- 定价页（提取套餐、价格、人数）

**关键字段**：
- 主页 Hero 文案
- "为什么选我们"对比表（如果有）
- Feature 列表
- 定价：免费版门槛 / 付费版起步价 / 企业版要不要询价
- 案例客户 logo

## 三、挖差评（B 端核心信号源）

**B 端的差评不在评论区——在 G2/Capterra 的 detractor reviews + Reddit + Twitter**。

### 可选渠道

| 渠道 | 用法 |
|------|------|
| **G2** | 搜产品名 → 排序按 "Lowest Rated" → 看 1-3 星评论 |
| **Capterra** | 同 G2，但更偏中小企业用户 |
| **Reddit** | 搜 `{产品名} sucks` 或 `{产品名} alternative` 或 `r/SaaS {产品名}` |
| **Twitter** | 搜 `{产品名} cancelled` 或 `{产品名} switch` |
| **TrustRadius** | 偏企业级用户 |

### 挖什么

- **流失原因**：用户为什么取消订阅
- **集成痛点**：用户抱怨跟现有工具不通
- **学习成本痛点**：用户说"太复杂"
- **价格痛点**：用户抱怨贵 / 收费模型不合理
- **客服痛点**：用户抱怨支持差

### 输出格式

每条记录：
```markdown
> "{用户原话引用}"
> 
> —— {用户名/角色}, {评分}, {来源 URL}, {评论日期}
```

## 四、行业 Benchmark

### 可能相关的指标

下表机构与报告名称仅作查找线索；实际数值须来自本次取得的真实资料，记录来源、日期、样本和适用范围，不能直接用作项目目标。

| 指标 | 需核对的统计口径 | 查找线索 |
|------|---------|--------|
| **MRR 月增长率** | 收入规模、企业阶段、月度周期及净增收入定义 | OpenView SaaS Benchmarks Report |
| **Churn 月流失率** | 客户流失或收入流失、期初分母、观察周期 | ChartMogul, ProfitWell |
| **NDR 净收入留存** | 同一客户群、扩张与收缩收入、流失及观察周期 | OpenView |
| **CAC 客户获取成本 / 回收期** | 分别核对获客成本、毛利口径与回收周期，不用 LTV 代替回收期 | OpenView |
| **LTV/CAC 比** | LTV 的收入或毛利口径、生命周期假设与 CAC 成本范围 | OpenView |
| **Sales Cycle 销售周期** | 客群规模、销售模式、起止事件及均值或分位数 | Pavilion, Gong |
| **Activation Rate 激活率** | 激活动作、注册样本、转化窗口与渠道 | Amplitude benchmark |
| **NPS** | 问卷对象、抽样方式、回复率与调查时间 | Delighted, SatisMeter |

### 行业报告数据源

- **OpenView Partners SaaS Benchmarks**（年度发布，免费）
- **ChartMogul SaaS Benchmarks**
- **Bessemer State of the Cloud**
- **a16z Enterprise Marketing Benchmarks**
- **Pavilion CRO/CFO Reports**

**找法**：联网搜索 `{品类} benchmark {实际年份} SaaS`，或直接读取上面这些报告的最新版

## 五、关键判断辅助

### 这个 SaaS 值不值得做的检查清单

- [ ] 目标客群的场景价值与付费依据是否清楚
- [ ] 用户群是否有"必须解决"的痛点而非"做了更好"
- [ ] 已确认成功标准及验证窗口是什么；没有依据时不预设达到 PMF 的期限
- [ ] 销售/营销渠道是否清晰（SEO/SEM/Outbound/PLG/合作伙伴）
- [ ] 是否有现成的整合点（接 Slack / 钉钉 / 飞书 / Salesforce 等）
- [ ] 数据安全/合规要求是否能扛（SOC2, GDPR, 等保）

### 中国 SaaS 特殊点

- 核对目标客群的真实预算与付费证据，不按海外收入统一折算
- 定制需求与采购能力按目标客户的实际流程确认
- 钉钉/飞书等生态是否需要接入，由既有使用环境和已确认范围决定
- 免费版、试用与付费分层按实际商业模式判断
- 数据合规：按业务与数据范围查证等保、数据出境等实际适用要求

## 六、调研输出模板

按实际查证内容写入 `{项目名}/evidence/competitors.md` 或 `benchmark.md`；未做的研究不生成空报告。

格式参考 `templates/evidence/competitors.md` 和 `benchmark.md`。

## 七、找不到数据时

诚实标注"未找到公开资料"。**严禁编造**。

如果某关键数据没找到，可以：
1. 在 assumptions.md 里加一条"待验证假设"
2. 按该数据影响的决定安排验证；已有数据或调研可先查，只有适合上线采集的证据才后置
