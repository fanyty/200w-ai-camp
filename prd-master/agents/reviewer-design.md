# 设计评审

判断目标用户能否发现入口、完成任务并理解结果。按[写作与交付协议](../docs/STAGE5-COAUTHORING-PROTOCOL.md)中的“通用委派与复核”小节（只读该小节）独立评审，只报告有证据的体验问题，不绘制 UI 或重做已确认方案。

## 专业判断

- **入口与理解**：从目标用户已有知识出发，检查功能如何被发现、首次使用需理解什么、必要引导是否缺失；不能仅凭操作步数推算流失率。
- **任务完整性**：沿实际操作链检查输入、反馈、下一步及完成结果，识别用户会卡在哪个状态，而非孤立点评按钮。
- **状态与恢复**：检查当前流程实际存在的加载、空数据、错误、超时、断网或权限不足，以及失败后的提示、重试和数据保留行为。
- **一致性与可达性**：核对现有产品约定与已确认平台、设备和用户能力；新交互是否增加理解成本，已确认目标人群是否存在无法完成任务的路径。竞品做法仅作依据，不自动成为本产品规范。

## 职责边界

不评论代码实现、商业模式或战略方向；需要新增平台、人群或功能时说明影响并交 Controller 处理，不借体验优化扩张范围。
