# 跨章节一致性评审

定位同一概念在不同章节中的冲突，给出可追溯的统一建议。按[写作与交付协议](../docs/STAGE5-COAUTHORING-PROTOCOL.md)中的“通用委派与复核”和“跨需求正确性分析”小节执行（只读这两节）；只在多主笔合并存在口径风险或出现具体疑点时运行。

## 检查方法

围绕实际疑点选择相关类别，必要时才读完整 PRD；用当前标题、稳定 ID 和行号定位，不假定固定章节编号。

| 类别 | 判断方法 |
|------|----------|
| 数字与阈值 | 比较数量、性能和完成指标的定义、适用范围及来源；先确认描述的是同一条件，再判断数字是否冲突。 |
| 术语与命名 | 比较角色、实体、状态和功能名称；已声明别名、机器状态与展示文案可并存，未声明映射导致歧义才报问题。 |
| 引用与覆盖 | 检查 US 引用的功能或 REQ、REQ 对应的 AC、指标对应的目标和跨章节引用是否真实存在，内容是否匹配。 |
| 决策与范围 | 比较已确认选择、本次 scope、详细功能和契约，查找实现假设是否偏离来源；不同阶段或不同方案不能混成同一决定。 |
| 时间口径 | 核对时区、频率、时间窗与格式及转换规则；存储与展示有明确转换时不要求字面一致。 |
| 量纲与单位 | 核对数值、单位、换算及舍入规则；不能只做文字替换来消除真实语义差异。 |

每条冲突引用双方位置与原文，说明为何不能同时成立、影响哪些需求，并以已确认来源或证据提出统一建议，不能任意认定某章节优先。P0/P1/P2 按协议中的实际后果分级；P1 不是可选建议，未解决前不能将受影响内容定稿。

## 职责边界

不直接修改 PRD，不审无关的单章节质量，不新增专业终审或作者互审轮次。修订由 Controller 分派；需要新产品决定时保留 `OPEN_QUESTION`，按授权边界处理。
