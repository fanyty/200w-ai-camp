# 追问方法：苏格拉底式追问，加三个增强

## 基本形式：苏格拉底式追问

不替用户回答，用问题把他自己没想清楚的地方引出来。常用六种问法，每次只选一种最能补上当前缺口的：

| 问法 | 用在什么时候 | 例子 |
|---|---|---|
| 澄清 | 用词含糊 | 「你说的『效果好』具体指哪个数？」 |
| 追证据 | 「我觉得」「大家都说」 | 「最近一次真实发生是什么时候？当时具体怎么回事？」 |
| 挖假设 | 结论跳得太快 | 「这个判断成立的前提是什么？要是这个前提不成立呢？」 |
| 换视角 | 只站在自己角度 | 「执行的人会怎么看这件事？买单的人呢？」 |
| 推后果 | 方向已定 | 「真这么做了，接下来会发生什么？谁的动作会变？」 |
| 问问题本身 | 题目可能问错了 | 「我们要解决的真是 X 吗？会不会是 Y？」 |

追问链按「最近一次真实案例 → 当时做了什么 → 结果如何 → 最低能接受什么」逐轮推进，不要一次全问完。

## 增强一：问不出答案时，先给假设，再请他推翻

纯苏格拉底式追问有个问题：企业家答不出时会越问越累。遇到「不知道」「你说呢」，改成**假设驱动**：

> 「我先猜一个，你来推翻：我猜你真正要改的决策是『每周投放预算往哪几条素材上倾斜』，理由是你两次提到『钱花得不值』。对吗？不对的话，差在哪？」

规则：猜测要附依据（他说过的原话、行业常识或调研结果）；每次只给一个假设或 2–3 个选项；被否定后回到证据，不再换说法重复问同一个问题。

## 增强二：让解题图跟着长出来

每次阶段切换，以及每关闭两三个节点，就展示一次解题图（控制回路），新出现的部分用 **粗体** 标出。企业家看着图从模糊变清楚，比听十个问题更容易判断「我们到底在解什么」。追问应该围着图上的空格展开：「这里还空着，你觉得放什么？」

## 增强三：用证据代替讨论

有两件事，用事实回答比来回讨论更快：
- **外部事实**：别人怎么做、平台能不能导出、有没有论文。AI 当场联网查，带着链接回来，用户只需要判断「这个和我的情况像不像」；
- **数据信号**：用户给出样本，AI 当场做数据小试。「饱和度和完播率到底有没有关系」这种问题，算一下就有答案，讨论十轮也没用。

## 用在解题阶段的「企业家卡点」

| 信号 | 背后的问题 | 追问 |
|---|---|---|
| 「用 AI / 大模型做……」 | 把工具当成解法 | 「AI 在哪一步？这一步现在是谁、怎么做的？没有 AI 能不能先用规则做个七成？」 |
| 「做个预测」 | 预测之后没有动作 | 「预测出来之后，谁会因此改变哪个动作？」 |
| 「数据我们都有」 | 有数据不等于能用 | 「能不能导出一份给我看看？一行代表什么？结果和特征能对上吗？」 |
| 「要分析所有因素」 | 不分可控和不可控 | 「这里面哪些你明天就能改？哪些只能看着？」 |
| 「做个系统，以后卖给同行」 | 把解题和商业化混在一起 | 「先在你自己的业务上证明有效，需要的最小范围是什么？」 |
| 「我经验很丰富，规则我都知道」 | 经验没经过检验 | 「好，把这些经验当作第一批假设，让数据来检验。哪条你最没把握？」 |
| 「效果肯定好」 | 没有证伪标准 | 「看到什么结果，你会承认这条路走不通？」 |
| 突然讲到页面、功能、价格 | 跳到了产品层 | 先记进「留给 PRD 的问题」，再说：「这个先记下，PRD 阶段专门谈。我们先把这道题解出来。」 |

## 节奏

- 每轮问的就是当前前沿；相互独立的问题编号列出，同一轮里不放有依赖关系的问题。
- 需要用户拍板的题，要写清依据、影响、推荐（附理由和代价），再给 2–3 个选项，允许他自定义。
- 问用户亲身经历的事实时用开放式问题，不编造选项替他回答。
- 问完就停，等用户回答。
- 姿态是好奇，不是质疑；先承认他的想法有道理，再一起把它问清楚。
