# 题型库与解法阶梯

企业家的大多数想法，都能归进少数几类题。先定题型，就知道经典解法、需要什么数据、通常的坑在哪。一个想法可以同时属于几类题，通常有一类是主题型。

## 一、题型

| 题型 | 企业家通常怎么说 | 核心问题 | 必要数据 | 经典解法 | 常见坑 |
|---|---|---|---|---|---|
| **归因** | 「为什么这几条火了」「哪些因素影响业绩」 | 哪些可控变量和结果相关 | 特征 + 结果，同一对象可关联 | 分组对比、相关分析（带 n）、可解释模型（EBM / SHAP） | 把相关说成因果；把事后才知道的变量当成原因 |
| **预测 / 排序** | 「上线前判断哪个好」「先做哪个」 | 新对象的结果大概会怎样 | 历史特征（事前可知）+ 结果，有一定样本量 | 基准线 → 线性模型 / 树模型，多模型同窗对照，给区间 | 追求精确值；用未来信息；样本太少还分组 |
| **策略 / 锦囊** | 「告诉我该怎么改」 | 在什么条件下改哪个杠杆、改多少 | 归因或预测的结果 + 可控变量的取值范围 | 模型响应 / 分组对照 → 条件化建议 → 小范围试验 | 重要性不等于方向；没有试验就说「能提升」 |
| **因果 / 实验** | 「这个动作到底有没有用」 | 改了 X，Y 会不会变 | 对照组，或足够的混杂变量 | A/B 测试、增量实验、DoWhy、因果森林、DiD | 没有对照只能算观察结论 |
| **异常 / 衰减** | 「哪个在变差」「该停哪个」 | 谁偏离了正常 | 时间序列 + 同期同批的对照 | 和同期同批比较、均值下降门、生存分析 | 整体都在下滑时，所有对象看起来都正常 |
| **能力复制** | 「把高手的做法复制给新人」 | 高手和普通人差在哪 | 高手和普通人的过程记录 + 结果 | 对比挖掘 → 规则或话术库 → 训练或陪练 → 回流 | 只抄话术，不看客户分层和条件 |
| **分配 / 优化** | 「预算、人、货怎么分」 | 约束下怎么分最好 | 响应曲线（投入对产出）+ 约束 | MMM、运筹优化、多臂老虎机 | 响应曲线没估准就开始优化 |
| **生成** | 「让 AI 写或做出好内容」 | 生成的内容怎么变好 | 好坏样本、评价标准或结果回流 | 策略驱动生成 → 多稿比较 → 采纳 → 回流 | 没有评价闭环，就只是批量生产 |
| **诊断 / 问答** | 「出问题时快速知道原因」 | 把专家诊断流程自动化 | 专家规则、案例、知识库 | 规则加 LLM 判定、RAG、决策树 | 规则没有出处、没人审核 |

多数「用数据改进业务」的想法，是 **归因 → 预测 → 锦囊 → 回流** 这条链（见案例「锦囊」）。认出这条链，就可以直接复用它的经验。

## 二、解法阶梯（从低到高，能用低一级解决的就不升级）

| 级 | 方法 | 什么时候够用 | 数据量级 |
|---|---|---|---|
| 0 | 经验规则 / 专家清单 | 没有数据，先把经验写成可检验的规则 | 0 |
| 1 | 描述统计、分组对比 | 想知道有没有信号 | 几十到几百 |
| 2 | 相关、可解释模型（线性、EBM） | 想知道哪些变量重要、方向如何 | 几百 |
| 3 | 预测模型对照（树模型等）+ 区间 | 要对新对象排序 | 几百到几千 |
| 4 | 因果方法 / 对照实验 | 要证明某个动作真的有用 | 视设计而定 |
| 5 | 优化 / 自动执行 | 响应已经验证、要规模化 | 大量，并有持续回流 |

**LLM 的位置**：把非结构化内容（文字、视频、录音）转成结构化特征（「判定命中没有」）；解释结果；起草锦囊和改稿。不让它直接算数，也不让它直接打分当预测值。

## 三、默认原则（来自实测）

1. 计算放进代码，LLM 只做判断。
2. 所有统计量都带样本量 n。
3. 终点结果给区间和排序，不给精确值。
4. 模型由数据选：同窗对照，训练、校准、验证三段划分，最后一段不参与挑选。
5. 人的经验当作候选假设，和数据发现的规则走同一套检验。
6. 无效的结论要明说。
