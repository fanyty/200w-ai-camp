# 调研指引（阶段 2 和阶段 3 的联网查证）

目的不是写行业报告，而是回答三个问题：**这类题别人怎么解？效果如何？数据能不能拿到？** 每条结论都要附 URL，找不到就写「未找到公开资料」。

## 查什么

| 方向 | 要找到的东西 | 搜索建议 |
|---|---|---|
| 同行做法 | 国内外 3–8 家在做同类事的公司或产品：怎么做、卖什么、价格、用户怎么评价 | 「行业 + 痛点 + AI / 数据」；海外用英文关键词；看产品官网、融资新闻、知乎、小红书、G2 上的差评 |
| 平台能力 | 目标平台（抖音、千川、视频号、淘宝、企微、ERP……）能导出哪些字段，有没有 API，有什么限制 | 官方开放平台文档、后台导出说明 |
| 论文 / 方法 | 这个题型的经典方法、基准成绩、已知局限 | Google Scholar、arXiv；「题型 + 行业 + survey」 |
| 开源轮子 | 可以直接用的库或项目 | GitHub：「方法名 + 场景」，看 star 数和最近更新时间 |
| 行业基准 | 指标的常见水平（比如完播率、复购率） | 平台白皮书、咨询机构报告；标明年份 |
| 前身项目 | 用户自己或公司做过的类似项目 | 问用户；能读到代码或文档的话，直接读它的实测结果 |

## 怎么交付

- 写入 `{项目名}/solution/evidence/`：`先例.md`、`数据可得性.md`、`方法.md`。
- 向用户汇报时只讲三到五条**会改变解题图**的发现：「查到 A 公司这样做，效果是 X（来源），这说明我们可以 / 不该……」。
- 证据冲突时，把冲突摆出来，不要替用户挑一个。
- 默认深度：先例 5 家左右、方法 2–3 种、关键平台的数据导出说明。题目高风险或证据冲突时再加深。
