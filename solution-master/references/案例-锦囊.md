## 二、四个关键问题，当时是怎么回答的

### 1. 用什么模型？

演变过程：LLM 打分 → LLM 判结构、代码算统计 → 从数据学权重 → 七个模型同窗对照 → 再加因果检验。

**真正的解法**不是挑出某一个模型，而是定下三条原则：
- 计算放在代码里，LLM 只做判断。让它「判定命中没有」，不让它「打几分」；
- 模型由数据选：同一批对象、同一时间窗公平对照，最后用没参与挑选的数据检验；
- 预测给排序和区间，不给一个精确的数。模型负责「引导先测哪几条」，最终由实际结果拍板。

### 2. 数据从哪来？

演变过程：千川或聚光单商家 → 没有客户数据，就用带已知关系的示例数据 → 刘润视频号自有数据 → 1200 条模拟实验（种入已知真相，检验系统能不能找回来） → 32 种数据格式模板 → NAS 视频经 GPU 提取特征。

**真正的解法**：
- 先问清能拿到的**特征数据**和**结果数据**分别是什么，再谈模型；
- 每个特征要标明「预测前就知道」还是「事后才知道」，事后才知道的不能用来预测；
- 手里没有真实数据时，先用「已知答案」的模拟数据验证方法本身。模拟数据得出的成绩不能说成业务效果；
- 现实是：到今天仍然没有真实的电商客户数据，这是最大的未验证风险。

### 3. 要不要产生锦囊？

演变过程：赢家模式报告 → 「先测哪三条」的排序 → 策略 → 锦囊。

**判断标准**：只有满足两个条件才值得做锦囊——用户手里**有可控的杠杆**，而且**会根据结论去动它**。否则做出来只是报告。锦囊的最小格式是：条件 + 动作（参数从多少改到多少）+ 预期结果 + 依据 + 样本量 n + 验证状态。

### 4. 要不要产生策略库？

演变过程：建议闭环（区分「建议差」和「执行歪」）→ 人的经验先当假设 → 策略带版本、可创作 → 审批入库 → 妙计库。

**判断标准**：同一类决策会反复发生、有多人执行、经验需要传下去、并且结果能回流，这时策略库就是这个控制回路的「记忆」。入库要分清「未验证经验」「历史观察」「已验证」三种状态，按版本追踪实际结果。观察到的结果不能说成因果提升。

（这一点和你在落地营给「微信复购」组的点评一致：核心是策略库，不只是话术。）

## 三、复盘：哪些做对了，哪些代价高

### 做对的
1. **先调研，再定框架**：第一天没有写代码，先做了五个方向的调研，定位在「素材智能层」。
2. **找到前身项目**：data-agent 已经把同一结构的题解过一遍，四条实测教训直接校准了预期，省掉了大量试错。
3. **从行业题提炼到一类题**：第三天就把「电商素材」提炼成「对象 + 表现」，后来视频号、公众号、门店数据都能接，全靠这一步。
4. **诚实规矩写进代码**：带样本量、不给点估计、无效明说。这三条后来成了产品可信度的来源。

### 代价高的
1. **变量分层来得太晚**。「可控 / 过程 / 结果」三层到 10-22 才出现，离开工已经五周。在此之前，框架只区分对象和表现，没有区分「能动的」和「只能看的」，所以策略和锦囊一直落不了地。**这本来应该是第一周就问清的问题**。
2. **输出形态最后才定**。产品名从「ROI 加速器」到「快速接入框架」再到「锦囊」，说明「最终交给用户什么」一直在变。10-22 晚上有几十次提交在改命名和布局，也就是说，解题思路是边做界面边想清楚的。
3. **没有真实数据就把系统建完了**。模型、因果方法、审批流都做了，但真实电商客户数据至今没有。数据源本该是第一道闸门：拿不到数据，就先用一份真实样本做一次「数据小试」，再决定往哪建。
4. **模型做加法比做减法多**。从 1 个模型到 7 个模型，再到 12 种高级方法。只要没问清「用户要做什么决策」，就容易靠堆方法来弥补。

### 如果重来，前两周就该问清的八件事
1. 想改进的是哪一个**决策**？谁做，多久做一次，做错一次损失多少？
2. 这个决策里，哪些是**可控变量**，哪些是**过程指标**，哪些是**结果指标**，哪些是外部环境？
3. 有没有人解过**同一类题**？包括竞品、论文、开源项目和自己的前身项目。
4. 特征数据和结果数据**现在手里有没有**？有多少条？能不能按对象关联？哪些是事前就能知道的？
5. 拿一份真实样本，做一次**数据小试**，看信号够不够强。
6. 要的是**报告、排序、锦囊还是自动执行**？
7. 结论要不要**沉淀成策略库**？由谁审批？怎么回流？
8. 怎么证明**它有效**？要设预测台账、校准，还是做对照实验？
