# 解题决策树（节点、依赖、关闭标准）

这是阶段 1–5 提问顺序和停止条件的唯一事实源。节点不是问卷：已经从上下文或证据中得到答案的，直接标为 resolved，不再重复问。

**前沿**：所有前置依赖都已解决、现在可以独立回答的节点。每轮问整个前沿（只包含真正独立的节点），回答后重新计算。
**类型**：事实（AI 查 / 用户告知）或决策（用户拍板）。

| ID | 节点 | 类型 | 依赖 | 关闭标准 |
|---|---|---|---|---|
| D1 | **要改进的决策**：谁、在什么时候、决定什么 | 用户告知 | — | 能说出一个具体角色和一个反复发生的决策，最好有最近一次真实例子 |
| D2 | **决策的分量**：频率、做错一次的代价、现在靠什么做（经验、规则、拍脑袋） | 用户告知 | D1 | 有频率量级和代价量级（用户估算也可以，要标明是估算） |
| D3 | **结果指标与方向**：真正想要的结果，越高越好还是越低越好，多久能看到 | 决策 | D1 | 有一个主结果指标；若有多个，要排出优先级 |
| D4 | **控制回路**：可控变量（杠杆）、过程指标、外部环境 | 用户告知 + AI 补全 | D3 | 至少列出 3 个可控变量和 1 个过程指标，每个都标明层级；用户确认分层 |
| D5 | **题型与先例**：属于哪类题，谁解过，效果如何，自己有没有前身项目 | AI 查 + 用户告知 | D1、D3（行业已知后即可开始查） | 题型已被用户确认；有 3 条以上带 URL 的先例，或明确写「未找到公开资料」 |
| D6 | **特征数据来源**：可控变量和环境变量的数据在哪、能不能导出 | AI 查（平台规则）+ 用户告知（内部系统） | D4 | 每个关键变量都有状态：已有 / 可导出 / 需采集 / 拿不到，并写明负责人 |
| D7 | **结果数据来源**：结果和过程指标在哪、回流周期多长 | 同上 | D3、D4 | 同上，并写明多久能拿到结果 |
| D8 | **对象与关联**：一行代表什么，用什么标识把特征和结果连起来 | 用户告知 + AI 判断 | D6、D7 | 对象定义清楚，关联键存在；不存在时写明补救方法 |
| D9 | **样本与时点**：样本量、时间跨度、每个特征是事前可知还是事后才知；有样本时做数据小试 | AI 查（有样本时）+ 用户告知 | D8 | 有 n 和时间跨度；事后才知的特征已剔除；小试结论（或「待小试」）已记录 |
| D10 | **方法路线**：解法阶梯的哪一级，AI 和 LLM 在哪一步 | 决策 | D5、D9 | 用户从 2–3 条候选路线中选定一条，知道放弃了什么 |
| D11 | **输出形态**：报告 / 排序和区间 / 锦囊 / 自动执行 | 决策 | D4、D10 | 见下方判断标准 |
| D12 | **策略库（记忆）**：要不要沉淀，谁审批，状态怎么分，怎么回流 | 决策 | D11 | 见下方判断标准 |
| D13 | **有效性证据**：怎么证明有效（预测台账和校准 / 对照实验 / 前后对比加局限说明） | 决策 | D3、D10 | 有基线、目标、时间窗，或明确的验证方法 |
| D14 | **最大风险与事前验尸** | AI 提出，用户确认 | D10 | 至少 3 条失败原因，每条有一个早期信号 |
| D15 | **最小切口**：一个场景、一个指标、一份数据、只给建议 | 决策 | D9、D10、D13 | 写清第一步做什么、谁提供什么；如果还没做过数据小试，第一步就是小试 |

## D11 输出形态判断

| 情况 | 推荐形态 |
|---|---|
| 用户手里没有可控杠杆，或者有杠杆也不会根据结论改动 | 报告 / 看板（诚实地说：这是诊断，不是控制） |
| 决策是「从一批候选里先选哪几个」 | 排序 + 区间（不给精确值） |
| 有可控杠杆，用户会照着做，而且能说清「在什么条件下改什么」 | **锦囊**：条件 + 动作（参数从多少改到多少）+ 预期结果 + 依据 + n + 验证状态 |
| 决策频率极高、单次风险低、回滚容易，并且已经过验证 | 自动执行（必须有审批或熔断） |

## D12 策略库判断

满足下面三条或以上，就推荐做策略库：同一类决策反复发生；多人执行；经验需要传承或复制；结果能回流到系统；有人愿意当审批人。
入库要区分三种状态：**未验证经验**（人提出的，可以先用）、**历史观察**（数据里看到的相关）、**已验证**（经过对照或前瞻检验）。每次修改出新版本，并按版本追踪实际结果。

## 停止闸门

只有同时满足下面四条，才能写《解题方案书》：

1. D1–D4、D6–D9 都已 resolved。或者用户明确接受某个未知项作为假设，并且这个假设有验证方法；
2. D10–D13 都由用户明确拍板；
3. 阻塞方向的未知（比如「结果数据根本拿不到」）不能靠假设绕过去，必须改路线或者把它作为最小切口的第一步；
4. 已向用户展示最终解题图和「已确认 / 仍是假设」清单，用户确认没有漏掉关键问题。

问题数量、耗时、用户一句「差不多了」，都不能作为停止的理由。如果用户坚持停下，就保存状态，标注为「未过闸门」，并列出缺了哪些节点。
